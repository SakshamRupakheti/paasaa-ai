# Conversational intelligence engine V1

## Existing architecture inspection
Plain JavaScript ES modules; CSS and static HTML; no frontend framework or TypeScript. A Node preview serves the same server API bundled by esbuild into a Worker. Authenticated user headers and same-origin checks gate requests. D1 records store owner-scoped JSON payloads with optimistic revisions; local preview uses SQLite with synthetic identity. Groq text and transcription requests are server-only; `.env.local` is ignored. No key values were inspected or copied.

The existing chat used a deterministic worksheet state machine and one Groq rephrasing call. It has persistent conversations, optional AI consent, voice approval, and a continuous chat UI. Existing support-content and support-model modules provide PMR muscle groups, 5-second tension/20-second release, breathing without holds, grounding, and pause/skip timers. Daily check-in remains separate. Existing safety is keyword-based and intentionally conservative. New layers must distinguish unwanted thoughts from intent in companion chat without rewriting the worksheet subsystem.

Tests use node:test; check is JavaScript syntax validation, not a linter or type checker. The project has no TypeScript configuration. Existing responsive pale-blue/navy styling is preserved. Intervention scripts are product drafts awaiting clinician review, not clinically approved treatments.

## Implementation report

1. **Existing architecture:** the inspection above records the reused frontend, API, storage, authentication, timers, and checks. Existing worksheet sessions remain on the prior state machine. New conversations use companion mode; an existing worksheet can switch through Chat freely. Worry records are not automatically rewritten by the engine.
2. **Files created:** `server/ai-config.js`, `ai-provider.js`, `engine-schemas.js`, `engine-prompts.js`, `engine-safety.js`, `engine-memory.js`, `engine-router.js`, `conversation-engine.js`, `engine-api.js`; `src/chat-interventions.js`, `chat-exercise.js`; `tests/engine.test.mjs`; `evals/cases.json`, `evals/README.md`, `evals/results/*`; `scripts/evaluate-engine.mjs`; this report.
3. **Files changed:** `server/ai.js`, `conversation-api.js`; `src/conversation-model.js`, `chat.js`, `styles.css`; `scripts/serve.mjs`; `.env.example`; evidence register and README. Existing support and worry modules are reused unchanged.
4. **Groq integration:** central environment-configurable defaults: conversation GPT-OSS 120B, planner GPT-OSS 20B, safety GPT-OSS Safeguard 20B. Server-only credentials. No paid fallback, browsing, code execution, or tools enabled. Each model call has a 12-second timeout, no automatic retries, and bounded output. Existing per-owner turn limit remains; provider quotas can be lower.
5. **Provider boundary:** `AIProvider` defines classifySafety, planTurn, generateResponse; GroqProvider implements HTTP transport. Another provider can implement that interface; no alternative provider is claimed implemented. Legacy structured calls reuse the transport; existing transcription retains its endpoint with centralized model configuration.
6. **Safety classifier:** local urgent detection runs before an independent structured classifier. Local urgent results cannot be downgraded. Unwanted-thought context is distinct from intent; ambiguous intent may produce one clarification. Urgent concerns persist through topic changes and resume. Medical escalation does not label symptoms anxiety. A failed classifier blocks new interventions and uses conservative human-support copy. This is routing, not a validated risk assessment.
7. **Planner:** receives the current message, at most eight bounded recent turns, structural session memory, safety result, and registry IDs. It chooses a tentative mode, need, arousal, and intervention, not a final reply or record mutation.
8. **Schema:** primary/secondary states, arousal, need, intent, response mode, optional intervention, intervention/question/science booleans, question purpose, max sentences, tone, avoid list, confidence. Runtime validation rejects unknown keys, invalid enums, types, bounds, and unavailable actions. Labels are not diagnoses.
9. **Router:** code overrides plans for urgent safety, clarification, stopping, no advice, no questions, breathing refusal, failed interventions, public settings, driving, recent injury, and repeated reassurance. It prevents repeat exercises after an unhelpful result unless explicitly requested. Returning an opening line is treated as an answer, not another question about that line.
10. **Prompts:** `server/engine-prompts.js`, versions 1.0.0. Identity, context-specific acknowledgment, short responses, one useful question, non-reassurance, no diagnosis/medication changes, and no invented exercises. Model output remains untrusted and is checked before display. The initial live tests found instruction invention, leading to stronger instruction checks and a contextual-introduction-only prompt for embedded exercises.
11. **Memory:** current turn is separate from bounded recent history and compact persisted structural memory. Environment, event, preferences, attempted/rejected interventions, outcomes, safety state, and optional first action are stored. No model-written narrative summary is trusted. Present refusal overrides prior preferences. No cross-session personal profile is inferred.
12. **Database:** no new tables or migrations. Existing owner-scoped conversation JSON gains companion, engineMemory, chatAction, chatSafety, awaitingFeedback, and bounded turnDecisions. Existing optimistic revisions protect writes. At most 30 technical decision records and 60 transcript turns are retained per conversation; earlier storage behavior for worksheets remains.
13. **Privacy:** AI requires explicit consent. No credentials, provider raw responses, or reasoning are stored. No external analytics. Technical decision records stay in the private account and are stripped from API responses. Unsent companion drafts stay in the tab. Recognized private thought content and potentially quoting replies are replaced with structural placeholders in durable chat; detection is imperfect and disclosed. Raw voice content is not persisted by the companion path. No private conversation is used as a training example.
14. **Safety assumptions:** trusted authentication comes from the hosting gateway; local preview uses synthetic identity. Crisis-resource UI is existing configured support, not model-generated phone numbers. Paasaa has contacted nobody. Content and classifier performance require qualified review, especially for ages 13-17. Lexical and model checks can miss cases or over-escalate; no clinical validation is claimed.
15. **Evaluations:** 56 initial synthetic routing cases plus boundary/integration regressions. The ten requested live scenario categories run through the real pipeline, with source, action, model/latency metadata, and unedited outputs recorded. Human 1-5 rubric scores remain unassigned. Initial and second runs are retained as failure evidence, not examples to imitate.
16. **Tests:** see final verification below. Browser checks used synthetic content: embedded PMR start, fixed instruction, Stop, listen-only/no-question refusal, reload continuity, and urgent medical support button. Existing worksheet tests remain in the suite.
17. **Lint:** no dedicated linter is configured. `npm run check` runs JavaScript syntax checks; it is not reported as lint.
18. **Type checking:** no TypeScript project or static type checker is configured. Runtime schema validation is implemented and tested; it is not a substitute for TypeScript or a clinical review.
19. **Known failures:** the first live run invented exercises, reoffered regulation, misclassified refusal, and exhausted free-tier limits. The second run still asked for an opening line already given and described grounding outside the registry; those observations prompted additional guards and first-action memory. Safer fallback text can sound repetitive. Final model quality is not represented by deterministic test pass rate.
20. **Remaining work:** qualified clinical/teen review, broader multilingual and adversarial evaluations, human naturalness scoring, microphone-device testing, longer conversation trials, retention/deletion policy review, and model comparison. The current request/response transport returns validated whole replies, not token streaming. First-token latency is therefore null rather than fabricated; safety/planner/completion/total timings are recorded. Streaming requires a separately reviewed transport and output-validation approach. There is no external reminder service or training-data collection.

## Intervention reuse
The registry reuses existing muscle groups, discreet variants, 5-second tension/20-second release, full-body two-round sequence, 4-in/6-out acute breathing without holds, and grounding. The main breathing page retains its existing timing choices. These are existing product scripts pending clinician review. Timers require Begin, expose Pause/Skip/Stop, stop when the page is hidden or left, and resume without catching up through unobserved tension phases. Static body highlighting respects reduced motion. No new clinical protocol was invented.

- 140 tests passed; 56 synthetic routing cases are included.

- Final browser checks verified the default companion conversation, fixed inline PMR instructions, Stop, refusal after reload, and the medical escalation button.

- Exercise introductions now use controlled registry copy. The generator does not write embedded physical instructions. Output checks also reject observed physical-instruction attempts in non-exercise modes.

- Known remaining quality limitations: canned phrasing, repetitive fallbacks, imperfect safety classification and privacy detection, and model attempts to add physical guidance that need rejection. This is an owner-private development preview pending clinical and broader adversarial review.
